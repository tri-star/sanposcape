# ADR-M-026: ピンタブの検索（住所・駅・施設名で探して地図に打つ）

## 現在有効な決定（要約）

> 最終更新: 2026-11-15（SS-272）。本節は本文（追補を含む）を要約したもので、一次記録は本文。
> 本文と食い違う場合は本節の誤りとして本節を直す。

### 決定

- **検索欄は情報カードの1行目（ヒントの行）を置き換え、サインインしていて地図が Google Maps のときだけ出す**。それ以外は従来のヒント。（本文: D1）
- **1回の送信で backend を1回呼び、範囲の広げ方（画面内 → 半径 50km を1段階）は backend が持つ**。（本文: D2）
- **地図を動かすのは、範囲を広げて見つけたとき（`expanded`）だけ**。先頭の結果の付近へ動かす。（本文: D3）
- **結果は虫眼鏡の「検索結果のピン」で打ち、タップで地図の下に概要のカード（名前・住所・閉じる・この場所にピンを登録）を出す**。（本文: D4、SS-272 追補）
- **クリアは検索欄の ×**。入力・結果のピン・案内をまとめて消す。（本文: D5）
- **結果はメモリ（`useMutation` の状態）だけに持ち、サインアウトで捨てる**。カードから登録して保存した位置だけは、ピンの座標として残る。（本文: D6、SS-272 追補）
- **カードの「この場所にピンを登録」で、検索結果の座標を初期位置にしてピンの登録画面（`/pins/new`）を開く**。長押しと同じ経路（`buildPinNewRouteParams`・push）で、
  その結果のピンとカードは外し、ほかの結果のピンは残す。名前は渡さない。Places の座標を無期限に残すことは規約（Service Specific Terms 14.3）に反するリスクがあり、
  承知のうえのユーザー判断（[ADR-001](../../../docs/adr/ADR-001-map-poi-google-maps-platform.md) の SS-272 追補）。（本文: D7、SS-272 追補）
- **コード上の名前は `locationSearch`**（walk の `placeSearch*` と分ける）。（本文: D8）

### 未解決・持ち越し

- 検索結果のピンとカード（登録のボタンを含む）は E2E で見ない。iOS の実機での確認。（本文: 移行・対応が必要な事項、SS-272 追補）

### 変更・撤回された決定

- D7「検索結果からピンを登録する導線は作らない」→ 検索結果の座標を初期位置にして登録画面を開く（SS-272 追補。規約に反するリスクを承知のうえのユーザー判断）

## ステータス

採用（SS-267）。D7 を変更（SS-272 追補）。フラグなし（iOS の地図の切り替えと同じストアのビルドで届けるため。下の D6）。

## コンテキスト

ピンタブの上部には「地図を長押しすると、その場所にピンを登録できます…」というヒントを出していた（ADR-M-011 の SS-146 追補）。
課題は、ここを入力欄にして、入力した文字に合う場所を地図に出すこと。例として次の3つが挙がっていた。

- 「コンビニ」のような種類: 現在地付近の該当する場所に「検索用のピン」を打ち、タップで概要（店名・住所など）を出す。ピン一式をクリアできる。
  まず画面内で探し、無ければ範囲を広げて探す（1段階で止める）のでもよい。
- 「○○区○○1-2-3」のような住所: 合う場所にピンを打ち、そこまで地図を動かす。
- 「○○駅」: 最も近い該当する駅（広い範囲なら複数ありうる）にピンを打ち、画面の外なら動かす。

検索元は Google Places の Text Search (New) を backend 経由で使う（[ADR-001](../../../docs/adr/ADR-001-map-poi-google-maps-platform.md) の SS-267 追補。
API は `POST /explore/places/text-search`）。Google Maps Platform の規約 3.2.3(e) が Places の内容を Google 以外の地図に出すことを禁じているので、
iOS の地図も Google Maps にした（[ADR-M-007](./ADR-M-007-expo-config-and-maps-key-injection.md) の SS-267 追補）。ここでは mobile の画面の決定を書く。

## 決定

- **D1: 検索欄は情報カードの1行目（ヒントの行）を置き換える。** サインインしていて、地図が Google Maps のとき（`currentMapRenderer() === "google"`）だけ出す。
  それ以外（サインインしていない・iOS でキーを入れていないビルド）は従来のヒントを出す（testID `pin-tab-hint` は E2E が見るので変えない）。
  長押しの登録の説明は、地図の `accessibilityHint` に残す。プレースホルダは「住所・駅・施設名で検索」。
  送信はキーボードの検索キーだけで、ボタンは足さない（地図の上の面積を増やさない）。
- **D2: 1回の送信で backend を1回呼ぶ。範囲の広げ方は backend が持つ。** 送るのは検索語（前後の空白を除き 100 code point まで）と、
  今の表示範囲（ピンの取得 `GET /pins` と同じく外側へ小数4桁に丸める）。backend が表示範囲の中だけを探し、0件なら範囲の中心から半径 50km を
  優先して1回だけ広げ、`scope`（`visible_area` / `expanded`）で返す。
- **D3: 地図を動かすのは、表示範囲の外まで広げて見つけたとき（`expanded`）だけ。** 先頭の結果（Google の関連度の順。並べ替えない）の付近
  （`regionAroundPoint`）へ動かす。表示範囲の中で見つかったときは、利用者が見ている範囲を変えない。動かすのはクラスタのタップと同じ `regionRequest`。
- **D4: 結果は「検索結果のピン」として打つ。** 虫眼鏡のアイコンの `MapPin`（`sky`。選んだものは `goal` で大きく）で、登録済みピン（地図のアイコン）と見分ける。
  重なりは登録済みピンより上。タップで地図の下に概要のカード（名前・住所・閉じる）を出す。「ここにピンを登録」は置かない（D7）。
  （**SS-272 追補**: カードに「この場所にピンを登録」を足した。下の D7 の SS-272 追補）
  案内は検索欄の下に1行: 0件（「「◯◯」に当てはまる場所は見つかりませんでした」）、広げて見つけた（「表示している範囲には無かったので、付近から探しました」）、
  失敗（429・503・通信・その他）。
- **D5: クリアは検索欄の ×。** 入力・結果のピン・案内をまとめて消す。入力を消した後でもピンが残っていれば × を出す。
- **D6: 結果はメモリだけに持つ。** TanStack Query の `useMutation` の状態に持ち、クエリのキャッシュ・端末のストレージには置かない
  （Places の内容を保存しない。古い要求の応答は、最後の `mutate` だけを映す v5 の挙動で捨てる）。ピンタブは常駐するので画面を離れても残るが、
  サインアウト（検索欄が消える）で捨てる。
  （**SS-272 追補**: 結果そのものは引き続きメモリだけに持つ。ただし、カードの「この場所にピンを登録」から利用者が保存すると、
  結果の位置（調整しなければそのまま）がピンの座標として DB に残る。D7 の変更）
- **D7: 検索結果からピンを登録する導線は作らない。** Places の座標をピンの位置として DB に無期限に残すことになり、規約（Places の内容の保存の制限）に
  触れうる。ピンの登録は従来どおり長押しで、利用者が選んだ位置を保存する。
  （**SS-272 追補**: この決定は変えた。下の「D7 の変更」）
- **D7 の変更（SS-272 追補）: カードの「この場所にピンを登録」で、検索結果の座標を初期位置にしてピンの登録画面を開く。**
  - 経路は長押しと同じ（`PinTabView` の `handlePick` → `buildPinNewRouteParams` → `/pins/new` へ push。`clientWalkId` なし）。登録画面は変えない
    （位置の調整・名前・タグ・最寄り駅のタグ。ADR-M-011・ADR-M-013）。
  - 押したら、その結果のピンとカードを地図から外す（`useLocationSearch` の `dismiss`）。位置を調整せずに保存して戻ると、
    検索結果のピン（登録済みピンより上に描く。D4）が新しいピンに重なって隠し、タップでカードがまた開いて同じ場所に二重に登録しうるため（レビューで指摘）。
    登録を破棄して戻っても外したままで、次の検索・クリアで戻る。ほかの結果のピンは残す（続けて別の結果から登録できる）。
  - 名前の初期値に検索結果の名前は入れない。Places の名前は一時キャッシュの許可も無いため（座標は 30 日まで）。
  - 規約: Service Specific Terms 14.3 は Places の緯度経度を 30 日までの一時キャッシュに限り、Address Validation API のような
    「利用者の確認で置き換えれば残してよい」例外も無い。登録画面で位置を確かめて保存しても、検索結果の座標を無期限に残すことは規約に反するリスクがある
    （条文と取得日は [ADR-001](../../../docs/adr/ADR-001-map-poi-google-maps-platform.md) の SS-272 追補）。
  - ユーザー判断（2026-11-15）: 規約に沿う2案（下の「検討した選択肢」の SS-272 追補）と比べたうえで、操作の短さを優先してこの案を選んだ。
  - カードの表示は `PinTabView` の関数の行数の上限（ADR-017）のため、同じファイルの補助コンポーネント `PinTabSearchResultOverlay` に分けた。
- **D8: コード上の名前は `locationSearch`。** walk の探索に `placeSearch*`（`/explore/places`）があるので分ける。置き場所は
  `features/sanpo-map/pin/{components,hooks,lib}/location-search/` と `features/sanpo-map/pin/api/locationSearchApi.ts`。

## 検討した選択肢

### 範囲の広げ方を mobile が持つ（画面内で探して0件なら mobile がもう一度送る）

- **メリット**: backend の API が単純になる。
- **デメリット**: 往復が2回になり、レート制限（1ユーザー 30 回/分）を2回ぶん使う。「1段階で止める」の規則が mobile と backend に分かれる。採らない。

### 検索のたびに結果に合わせて地図を動かす（全件が入るように寄せる）

- **メリット**: 結果が必ず画面に入る。
- **デメリット**: 表示範囲の中の検索で、見ている範囲が勝手に変わる。広げた検索では遠くの結果が混ざると日本全体まで縮む。
  課題の「画面外の場合はスクロールして表示」に合わせ、広げたときだけ先頭へ動かす。

### 結果をリストでも出す

- **メリット**: 地図で重なった結果も選べる。
- **デメリット**: 地図の上の面積を取る。最大 20 件で、課題はピンとタップの概要を求めている。まずピンだけにした。

### 検索結果から「ここにピンを登録」

- D7 の理由で採らない。必要になったら、Places の座標を保存してよいか（規約の確認）と合わせて決め直す。
  （**SS-272 追補**: 規約を確かめて決め直し、検索結果の座標で開く案を採った。D7 の変更）

### 登録画面を位置未定で開き、利用者がタップで位置を決める（SS-272 追補）

- **メリット**: 保存する座標は利用者の操作から生まれるので、Places の座標を残さない（規約に沿う）。地図は検索結果の付近に寄せて開ける。
- **デメリット**: 登録画面に「位置が未定」の状態を足す必要がある（今は `/pins/new` が座標を必須にしている）。操作が1つ増える。ユーザーが採らなかった。

### ピンタブで検索結果の付近に寄せ、長押しを案内する（SS-272 追補）

- **メリット**: 規約に沿い、変更が小さい。
- **デメリット**: ボタンは寄せて案内するだけで、登録の手間は長押しと変わらない。ユーザーが採らなかった。

## 決定理由

- 課題の3つの例（種類・住所・駅）は Text Search の1回で扱え、範囲の広げ方を backend に寄せれば mobile は送るだけになる。
- 地図を勝手に動かさない（表示範囲の中の検索）ことと、見つけた場所まで連れていく（広げた検索）ことを、`scope` だけで切り替えられる。

## 影響

### ポジティブな影響

- 住所・駅・施設名から、その場所の付近の地図にすぐ移れる。長押しでピンを登録する起点にもなる（SS-272 追補: カードの「この場所にピンを登録」から直接、登録画面を開ける）。

### ネガティブな影響・トレードオフ

- ヒントの行が消えるので、長押しで登録できることは画面の文字では伝わらなくなる（スクリーンリーダーには `accessibilityHint` で伝わる）。
- 検索語（住所を含みうる）と表示範囲が backend を通って Google へ送られる（DB・ログには残さない。データ取扱い台帳 3.1）。
- iOS でキーを入れていないビルド（ローカルの dev build など）では検索欄が出ない。

### 移行・対応が必要な事項

- 検索結果のピンとカードは E2E で見ない（Google Maps の描画面で testID が安定して取れない。ADR-M-012 D14）。E2E は案内とクリアだけを見る（`.maestro/pin-tab-search.yaml`）。
  （SS-272 追補）カードの「この場所にピンを登録」も同じ理由で E2E では見ない。
- iOS の実機での確認（検索欄・ピン・カード・地図を動かす）。
