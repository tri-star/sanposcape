# プロジェクト概要: sanposcape（散歩支援アプリ）

> 作成日: 2026-07-19

## 1. プロジェクトの目的・背景

### 1.1 解決したい課題

- 散歩をしたいが「どこへ・どのくらいの時間で歩くか」を決めるのが面倒で、結局いつも同じ道になったり、外出そのものをやめてしまう。
- 歩いている途中で見つけた気になる場所（お店・景色・史跡など）を、あとで思い出せる形で残す手段がない。
- 「今いる場所から、決めた時間内で往復できる範囲」という散歩に特化した探索軸を満たすツールが少ない。

### 1.2 プロダクトの概要

sanposcape は「散歩」に特化したモバイルアプリ + バックエンドAPIのサービス。

- **ルート計画**: 現在地と「往復にかけたい時間」を指定すると、その時間で往復できる範囲にあるスポット候補を地図上に提示し、目的地・ルートを決められる。
- **散歩の記録**: 歩いている途中で見つけたスポットを、位置・写真・メモとともにその場で記録し、あとから振り返れる。

モバイルは React Native (Expo)、バックエンドは FastAPI + PostgreSQL。地図・POI・徒歩ルーティングは Google Maps Platform を利用する。

## 3. MVP (Minimum Viable Product)

### 3.1 MVP の定義

以下の単一フローを、モバイルアプリ + バックエンドの縦の連携で通しきる:

**スプラッシュ →（保存済みセッションがない場合はサインイン/サインアップ）→ 散歩開始画面（往復時間内のスポット検索・スポット選択で開始）→ 散歩中の状況表示 → 散歩終了（歩いたルートの記録）→ 散歩履歴画面**

加えて、アカウント運用に必要な **ログアウト** と **アカウント削除** を含む。認証・実機依存機能（位置情報など）は services 層でスタブ差し替え可能にし、自動テストを回せる状態を保つ。

### 3.2 MVP に含まれる機能一覧

| # | 機能名 | 概要 | 優先度 |
| --- | --- | --- | --- |
| 1 | スプラッシュ画面 | 起動時の初期化。認証状態の復元は `AuthGate`（ルートレイアウト）が担い、スプラッシュは復元確定まで待って遷移を振り分ける | Must |
| 2 | サインアップ / サインイン | Google サインインによるログイン（初回は backend が JIT でユーザー作成） | Must |
| 3 | ログアウト | 散歩中画面の設定ボタンから設定画面を開き、画面下部の操作でセッションを破棄してサインイン画面へ戻る | Must |
| 4 | アカウント削除 | ユーザーと関連データを削除する（backend側の削除APIを含む） | Must |
| 5 | 現在地取得・地図表示 | 位置情報を取得し地図上に現在地を表示（services層でスタブ差し替え可能に） | Must |
| 6 | 往復範囲のスポット検索・提示 | 「往復◯分」を指定 → Google Places/Routes で範囲内のスポット候補を地図・リスト表示 | Must |
| 7 | スポット選択で散歩開始 | 候補から目的地を選び、徒歩ルートを提示して散歩を開始 | Must |
| 8 | 散歩中の状況表示 | 現在地・経過時間・目的地/ルートなど散歩中の状況を表示 | Must |
| 9 | 散歩終了・ルート記録 | 実際に歩いたルート（軌跡・所要時間・距離）を保存 | Must |
| 10 | 散歩履歴画面 | 過去の散歩（ルート・所要時間）の一覧・詳細を閲覧 | Must |

### 3.3 MVP に含めないもの（スコープ外）

- **ゲストでの散歩開始（記録なし）** — MVPでは認証必須とし対象外。ただし将来サインイン前でも散歩を試せるようにする構想があるため、**設計段階で意識しておく**（下記 5.2 参照）。
- 散歩途中で見つけたスポットの記録（写真・メモ付き） — 将来機能へ移動（下記 5.1 参照）。
- SNS的な共有・フォロー・コメントなどのソーシャル機能
- オフライン地図・オフライン動作
- 音声ナビゲーション / ターンバイターンの案内
- スポットのレコメンド最適化（好み学習・パーソナライズ）
- 複数人での散歩計画・待ち合わせ

## 5. 最終的なゴール（ビジョン）

散歩を「思い立ったときに、負担なく、毎回すこし新しい体験として楽しめる」状態にする。集めたスポット記録が個人の散歩地図として育ち、季節・時間帯・気分に応じた散歩先の提案につながることを目指す。

### 5.1 将来追加を検討している機能

- **散歩途中で見つけたスポットの記録**（位置・写真・メモ） — 当初構想の中核だが、今回のMVPフロー外のため将来追加。
- **ゲストでの散歩開始**（サインイン前に記録なしで散歩を試せる） — 5.2 の設計考慮事項を参照。
- スポット記録の蓄積を活かしたパーソナライズされた散歩先レコメンド
- 季節・天気・時間帯を考慮したルート提案
- 散歩実績の可視化（歩いたエリアのマップ塗りつぶし・統計）
- 家族・友人との散歩スポット共有（ソーシャル機能）

### 5.2 スケーラビリティ・拡張性に関する考慮事項

- **ゲスト（未認証）での散歩を見据えた設計** — MVPでは「スプラッシュ→認証」を必須ゲートとするが、将来「サインインせず記録なしで散歩開始」を追加する構想がある。そのため、散歩の探索・開始・散歩中表示のロジックが**ユーザー認証に不可分に依存しない**よう分離しておく（記録・履歴の永続化のみが認証を要求する形にする）。認証状態の判定元は `src/store/useAuthSessionStore`（`loading | authenticated | guest`）に集約し、画面遷移のゲート（`AuthGate`。弾く条件は `canEnterProtectedRoutes` 1関数）は差し替え可能にしておく（mobile [ADR-009](../packages/mobile/adr/ADR-009-auth-session-state-and-route-gate.md) 参照）。
- スポット/記録データは位置情報を持つため、将来の地理検索を見据え PostGIS 等の地理空間拡張への移行余地を残す（MVPは緯度経度カラム + 単純検索でも可）。
- Places / Routes のデータ API はコスト・レート制限があるため、backend 側のキャッシュ・プロキシ層を通す（SS-14 で実装）。地図描画の native SDK 通信は mobile 側の責務として分離している（SS-15。`app.config.ts` が mobile 用の Maps SDK キーを注入し、backend の server key とは別キーにする）。
- 実機依存機能（位置情報・カメラ）と認証は services 層でスタブ差し替え可能にし、テスト容易性とCI実行性を維持する。

## 6. 制約・前提条件

- ローカルのE2E（Maestro）で Android を使う場合、WSL2 ではなく Windows 側で動作させる必要があり、一部ユーザーの協力が前提。
- 開発環境は WSL2/Linux（大文字小文字を区別）。import パスは実ファイル名と case まで完全一致させる。
- mobile の依存追加は minimumReleaseAge を設定し、公開から2日以上経過したバージョンのみ利用する。
- Google Maps Platform / Google Cloud（Maps・OAuth クライアント）の利用にはアカウント・APIキー・課金設定が必要（キーは環境変数管理、リポジトリにコミットしない）。Android は署名鍵ごとに SHA-1 の登録が必要。
- 初期化・セットアップは各ツールの公式ドキュメントを参照した手順で行う。

## 7. 用語集

| 用語 | 定義 |
| --- | --- |
| スポット (Spot) | 散歩の目的地候補・記録対象となる地点（店・景色・史跡など） |
| 往復範囲 | 現在地から指定時間内に徒歩で往復できる地理的範囲 |
| 散歩ルート (Walking Route) | スポット選択時に提示される徒歩の推奨経路。実際に歩いた軌跡は「軌跡 (Track)」として別語に分ける（SS-18 でコード上も分離）。**Expo Router / React Router の「ルート(route＝画面/URL)」とは別概念**。コード上は walking-route / walkingRoute 等と表記し、画面遷移の route と混同しない |
| 軌跡 (Track) | 実際に歩いた経路。散歩の記録として履歴に保存する。コード上は track / track_points と表記し、提示経路の walking-route と区別する |
| 記録 (Record) | ユーザーが散歩中に残したスポットの記録（位置・写真・メモ・日時）。※MVPでは散歩ルートの記録が対象で、スポット単位の記録は将来機能 |
| services層 | 認証・位置情報・カメラ等の実機依存機能を抽象化し real/stub を差し替える層 |
| Orval | OpenAPI定義からAPIクライアントとMSWモックを生成するツール |
