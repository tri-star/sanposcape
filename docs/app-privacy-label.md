# App Store の App Privacy（プライバシー栄養ラベル）の申告内容

App Store Connect の「App のプライバシー」に入力する内容と、その根拠をまとめる（SS-159）。
入力はこの文書を正本として手作業で行う。App Privacy の回答は App Store Connect からいつでも更新でき、
アプリの更新（審査）は要らない。

> ⚠️ **成熟度（2026-10-10 時点）**: まだ App Store Connect に入力していない（アプリレコードの作成と合わせて入力する）。
> 入力時に画面の項目名・選択肢がこの文書と違えば、この文書を訂正すること。

## 1. 前提: Apple の定義の要点

出典: [App privacy details on the App Store](https://developer.apple.com/app-store/app-privacy-details/)

- **収集（collect）**: データを端末の外へ送り、リクエストへの応答に必要な時間より長く、
  運営者または第三者パートナーが読める形で保持すること。送って処理後すぐ捨てるもの、端末の中だけで処理するものは対象外。
- **ユーザーに紐づく（linked）**: 収集前に匿名化などの措置をしていなければ、原則として紐づく扱い。
  法令上の個人情報は紐づく扱いになる。
- **トラッキング**: 収集したデータを他社のデータと結び付けて広告のターゲティング・効果測定に使うこと、
  またはデータブローカーに渡すこと。
- **第三者パートナー**: アプリに組み込んだ SDK などが収集するデータも申告する。**Apple（MapKit など）が収集するデータは申告不要**。
- **IP アドレス**: 使い方に応じて、該当するデータの種類（位置、デバイス ID、診断など）として申告する。

## 2. 申告内容（App Store Connect に入力するもの）

### 2.1 全体の回答

| 質問 | 回答 |
| --- | --- |
| このアプリでデータを収集しますか | **はい** |
| トラッキングに使うデータがありますか | **いいえ**（すべてのデータの種類で「トラッキングに使用しない」） |
| プライバシーポリシーの URL | `https://sanposcape.com/privacy/` |
| ユーザーのプライバシー選択の URL（任意） | `https://sanposcape.com/privacy/#delete`（削除方法の節） |

### 2.2 データの種類ごとの回答

「目的」の略記: **機能** = App Functionality（アプリの機能）、**分析** = Analytics（分析）。

| カテゴリ | データの種類 | ユーザーに紐づく | トラッキング | 目的 |
| --- | --- | --- | --- | --- |
| 連絡先情報 | 名前 | はい | いいえ | 機能 |
| 連絡先情報 | メールアドレス | はい | いいえ | 機能 |
| 健康とフィットネス | フィットネス | はい | いいえ | 機能、分析 |
| 位置情報 | 正確な位置情報 | はい | いいえ | 機能、分析 |
| ユーザコンテンツ | 写真またはビデオ | はい | いいえ | 機能 |
| ユーザコンテンツ | その他のユーザコンテンツ | はい | いいえ | 機能、分析 |
| ID | ユーザ ID | はい | いいえ | 機能 |
| ID | デバイス ID | **いいえ** | いいえ | 機能 |
| 診断 | パフォーマンスデータ | はい | いいえ | 機能、分析 |
| 診断 | その他の診断データ | はい | いいえ | 機能、分析 |

上の表に無いデータの種類は、すべて「収集しない」。

## 3. 根拠

### 3.1 申告するもの

| データの種類 | 実際のデータ | 根拠（実装） | ポリシー |
| --- | --- | --- | --- |
| 名前 | Google から受け取る表示名（`users.display_name`） | `auth/providers/google.py`、`users/models.py` | 1-2 |
| メールアドレス | Google から受け取るメールアドレス（`users.email`）。重要なお知らせの連絡にも使うが、マーケティングには使わない | 同上 | 1-2、2 |
| フィットネス | 散歩の記録の歩いた時間・距離（`walks.duration_seconds` / `distance_meters`）。Motion & Fitness API・HealthKit は使っていないが、運動の記録にあたるため申告する | `walks/models.py` | 1-1 |
| 正確な位置情報 | 散歩の軌跡（小数 6 桁）、目的地の座標、ピンの座標。スポット・ルート検索の現在地（小数 4 桁 ≒ 11m）とピン地図の表示範囲もアクセスログに残りうる。Apple の定義では小数 3 桁以上は「正確」 | `walks/models.py`、`sanpo_maps/models.py`、mobile の `walkTrackPayload.ts` / `placeSearchRequest.ts` / `pinFetchBounds.ts` | 1-1、1-5 |
| 写真またはビデオ | ピンに添付する写真（S3）。Google のプロフィール画像の URL（`users.photo_url`）もここに含める | `sanpo_maps/photos/`、`users/models.py` | 1-2、1-3 |
| その他のユーザコンテンツ | ピンの名称・メモ・タグ、地図（sanpo map）の名称 | `sanpo_maps/models.py`、`pins/schemas.py` | 1-3 |
| ユーザ ID | Google アカウントの ID（`users.provider_subject` = sub）、アカウントの内部 ID（`users.id`） | `users/models.py` | 1-2、1-5 |
| デバイス ID | `expo-updates` が更新の確認時に Expo へ送る、インストールごとに生成されるランダムな識別子。Expo は「端末固有の識別子は含まない」としているが、Expo 側に保持されるため申告する。運営者のデータと結び付けないので「紐づかない」 | `packages/mobile/app.json` の `updates.url`、[Expo: Privacy explained](https://expo.dev/privacy-explained) | 3（Expo の行） |
| パフォーマンスデータ | backend のトレース（ADOT / Application Signals。処理時間など）、アクセスログの処理時間 | `core/observability.py`、ADR-013 | 1-5 |
| その他の診断データ | backend のログ（アカウントの内部 ID を含む行がある）、CloudFront のアクセスログ（IP アドレス、URL、ブラウザ・アプリの種類）。最長 400 日保存 | `core/observability.py`、`template.yaml`（ロググループの保持期間）、ADR-005（アクセスログ S3 は infra 所有） | 1-5、6 |

「紐づく」は、アカウント（内部 ID）と結び付けて保存しているため。診断データも、ログにアカウントの内部 ID や IP アドレスが含まれるため「紐づく」とする。

### 3.2 申告しないもの

| データの種類 | 申告しない理由 |
| --- | --- |
| おおよその位置情報 | IP アドレスから位置を推定していない。送信する位置はすべて「正確な位置情報」に含めている |
| 検索履歴 | アプリから検索語を送っていない（`GET /pins` の `q` / `tags` は API にあるが、mobile は送らない。`pinFetchBounds.ts`）。スポット探索は現在地からの候補の取得で、文字列の検索ではない |
| 認証トークン | サーバーには照合用のハッシュだけを保存し、読める形で保持しない |
| 製品の操作（Product Interaction）などの使用状況データ | アクセス解析のツールを組み込んでいない。backend のアクセスログはリクエスト単位の記録で、診断データとして申告している |
| クラッシュデータ | クラッシュ解析のツールを組み込んでいない（mobile の依存に Sentry・Firebase などが無い） |
| 広告データ・購入履歴・財務情報・連絡先・健康・機密情報・音声・閲覧履歴など | 該当する機能が無い（マイクの権限も要求しない） |
| 地図の表示で送られる情報（iOS） | iOS の地図は Apple MapKit。Apple が収集するデータは申告不要 |
| Google でサインインの手続き | 端末と Google の間のやり取り。運営者が受け取る情報（名前・メールアドレス・ユーザ ID・プロフィール画像の URL）は上で申告している |

### 3.3 判断が分かれたもの

| 論点 | 判断 | 理由 |
| --- | --- | --- |
| 「分析」の目的を付けるか | 正確な位置情報・フィットネス・その他のユーザコンテンツ・診断データに付ける | ポリシーの「2. 利用目的」に「本アプリの改善や新しい機能の開発」「統計情報の作成」がある。Apple の Analytics は「機能の効果の把握・新機能の計画」を含むため、付けないとポリシーと食い違う。アクセス解析ツールは組み込んでいない（ポリシー 1-6）が、目的とツールは別の問い |
| フィットネスを申告するか | 申告する | 散歩の時間と距離は運動の記録にあたる。位置情報から算出した値で、Motion & Fitness API は使っていない（`NSMotionUsageDescription` の文言どおり）が、データの種類としては該当する |
| ピン・写真を申告するか | 申告する | ピンの登録（写真の添付を含む）は `pin_registration` フラグの裏にあり既定 OFF だが、フラグはアプリの更新なしに ON にできる（`packages/backend/feature-flags.json`）。写真については、プロフィール画像の URL も保存している |
| Expo のインストール ID を申告するか | デバイス ID（紐づかない）として申告する | ポリシーの外部サービスの表に「インストールごとに生成される識別子」と書いており、申告しないとポリシーと食い違う |

## 4. 入力手順

1. App Store Connect でアプリを開き、「App のプライバシー」を選ぶ
2. 「プライバシーポリシー」に `https://sanposcape.com/privacy/` を入力する（「ユーザーのプライバシー選択」は任意）
3. 「はじめに」から、データを収集するかに「はい」と答える
4. 2.2 の表のデータの種類にチェックを入れて保存する
5. データの種類ごとに、2.2 の表のとおり目的・ユーザーに紐づくか・トラッキングを答える
6. プレビューを確認して「公開」する（審査とは別に公開できる）

## 5. 見直すタイミング

次のいずれかを変えたら、この文書と App Store Connect の回答、[プライバシーポリシー](../packages/lp/src/pages/privacy.astro)の 3 つを揃えて更新する。

- 新しく保存・送信するデータを増やす（例: ピンの検索 UI を付けて検索語を送る → 検索履歴を申告する）
- SDK を足す（クラッシュ解析・アクセス解析・広告など）。SDK が収集するデータも申告対象になる
- データを他の利用者と共有する機能を作る（地図の共有など）
- データを広告・マーケティングに使う、または他社のデータと結び付ける（トラッキングの回答が変わる）

## 6. この文書の対象外

- **Google Play の「データ セーフティ」**: 項目の分け方が App Store と違うため、別に整理する。Android は地図に Google Maps SDK を使うので、App Store にない申告が要る。
- **プライバシーマニフェスト（`PrivacyInfo.xcprivacy`）**: アプリのビルドに含めるファイルで、App Privacy の回答とは別物。
  `app.json` に `ios.privacyManifests` の設定は無い。
