# 観点の型

候補は実際の変更に合わせて具体的な問いにする。ファイル名だけで動作を推測せず、観点を選んだ後で関係箇所を確かめる。

| 変更 | 問いの例 | 訪問順の目安 |
| --- | --- | --- |
| 画面とAPIの両方 | 操作から保存・表示まで何が起きるか | 画面 → hook → API → service → repository → 結果 |
| DB migration | 既存行とロールバックに何が起きるか | migration → model → 読み書き → downgrade |
| 削除 | 関連データや外部保存物も消えるか | 入口 → service → FK/明示処理 → 外部保存 → 再取得 |
| 外部API・ストレージ | 遅延・失敗時にどう見え、後始末されるか | 呼出し → timeout/retry → エラー → 後始末 |
| 認証・認可 | 他人の資源を指定するとどうなるか | 認証依存 → 所有者判定 → 応答 → テスト |
| API契約 | 旧クライアントを壊さないか | router → schema → エラー → OpenAPI/生成物 → client |
| 状態管理・画面 | 読込中・失敗・空・再開をどう扱うか | 入口 → 状態遷移 → 表示 → テスト |
| 設定・環境 | 本番とローカルで何が切り替わるか | 設定値 → 分岐 → 各実装 → 確認手順 |
| テスト・同型変更 | どの分岐や例外が残るか | 代表例 → 全対象一覧 → 例外 → テスト |

ADR・CI・デプロイ等も変更内容に応じて候補へ加える。候補は話題名ではなく、終わりに答えを確認できる問いにする。
