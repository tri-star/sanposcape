# 完了時の知識整理

メインが [知識の置き場所](../../../../docs/knowledge-management.md) に従い、今回の課題で生まれた記録を整理する。専用SubagentやClaudeのメモリフックを前提にしない。

## PR作成・レビュー修正後

1. 対象課題・作業ディレクトリ・PR・ブランチを照合し、申し送り事項がPR本文へ反映済みか確認する。課題の状態同期が失敗していても独立した整理は進めてよいが、未反映内容と再試行に必要な情報を残す。
2. 一時記録にしか残っていない設計判断を [adr-writing](../../adr-writing/SKILL.md) で記録する。既存ADRに追補した場合は要約も更新する。重複したADRは作らない。
3. メモリの永続化・削除・統合は、ユーザーの依頼と実行環境のメモリ規則が許す範囲に限る。Claude側の自動モードを根拠に許可を拡張しない。許可がなければ候補・未処理として報告する。Planeの状態など変動する情報は保存せず再取得する。
4. 繰り返し使えるレビュー観点は `.agents/skills/change-review/references/` の該当資料へ反映する。規約・ADRの書き写しや今回限りの指摘は足さない。依頼範囲と実行環境の編集権限に従い、未反映なら候補を報告する。
5. 変更に応じた文書検査を行い、今回の変更だけをコミットして同じPRへpushする。知識検査のbaselineは実際に解消した違反だけを規定手順で減らし、検査を通すための追加や無関係なimport基準更新はしない。
   - 共有の [ログ移し込み](../../../../scripts/knowledge/flush-memory-access-log.sh) をコミット前に実行する（`bash scripts/knowledge/flush-memory-access-log.sh`）。Claudeフックの自動実行はCodexに無いが、共有spoolの実ログはこの手順で移せる。出力された移動件数と対象ファイルを確認し、試験の記録を含めず、確認した移動ファイルだけを明示的にstageする。他の未コミット変更は含めない。
   - worktreeからgit共通ディレクトリへの書き込みが権限で失敗したら、依頼範囲内でSandbox外の実行を検討する。許可されなければ手元のログと再開情報を保持し、実行用スクリプトを用意してユーザーへ報告する。ログ移し込みの失敗だけで独立したADR・文書整理を止めない。
6. 整理したADR・許可されたメモリ変更・レビュー観点・移動したアクセスログ・未処理事項をPR本文の「知識の収穫」に反映する。レビュー修正時は既存節を更新し、重複を避ける。対象がなければ節を省略する。
7. 必要な情報の移記、push、PR本文の更新が成功し、未処理事項や再開に必要な情報が失われないことを確認してから、今回の `tmp/<issue-id>/`（IDなしなら開始時に決めた作業ディレクトリ）と対応する `tmp/<PR番号>-comments.md` だけを削除する。削除前に実パスがリポジトリの `tmp/` 内の対象であり、symlinkや別作業の記録を含まないことを確認する。計画・進行中の記録や、外部更新失敗時に必要な記録は保持し理由を報告する。

最終報告では変更・検証・外部更新の成否と、削除または保持した一時記録を示す。メモリ操作が許可されないことだけで、他の完了作業を止めない。

## マージ後の取りこぼし

対象PRのマージと課題状態の同期を確認した後、対象の一時記録や `source_issue` が一致する `scope: task-local` の記録が残る場合だけ調べる。残っていなければ整理済みとして終了する。

残っている場合は内容と必要な処理を報告し、現在の依頼範囲で進める。マージ済みPRのブランチには追加pushしない。追加の文書修正が必要で、ブランチ作成・PR作成まで依頼されている場合は最新mainから別ブランチ・PRで扱う。残存ファイルの存在だけを削除の根拠にせず、上記の移記確認とメモリ規則を守る。

## 定期の文書確認

週次〜月次の棚卸しを依頼された場合は、main全体を対象に前回以降の改名・削除・設定/契約変更を逆引きし、[文書の確認観点](../../change-review/references/docs.md)と文書参照検査で、ワークフロー外の変更による乖離も確認する。現worktreeを勝手に切り替えず、確認対象のmainコミットを記録する。調査依頼なら指摘だけ返し、修正や外部投稿に範囲を広げない。
