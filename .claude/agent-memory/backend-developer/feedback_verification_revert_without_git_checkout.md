レビュー対応で書いた修正が本当に効いているかを確認するため、一時的にソースを元の（バグがある）
状態に書き換えて `pytest` を実行し、テストが red になることを確認してから戻す、という手順を
踏むことがある。この「戻す」操作に `git checkout -- <file>` を使うと、その時点でまだ一度も
commit していないファイルは HEAD（＝レビュー対応前の状態）に巻き戻り、自分がそれまでに書いた
修正そのものが消える。

**Why**: `git checkout -- <path>` はワーキングツリーをインデックス（未ステージなら HEAD）の
内容に戻すコマンドであり、「直前の編集を取り消す」コマンドではない。未コミットの一連の変更を
検証目的で一時的に壊す/戻すサイクルに使うと、意図せず全履歴を失う。

**How to apply**:
- 一時的に壊す→検証→戻す、というサイクルを踏むときは、`git checkout` ではなく手動で元の
  文字列に戻す（Edit ツールで壊した箇所だけを逆方向に置換する）。
- どうしても git 由来の操作で戻したいなら、壊す前に必ず WIP コミットを作ってから壊し、
  検証後に `git diff` で差分を確認してから `git reset` する（`git stash` は使わない。
  他セッションと stash スタックを共有しているため）。
- 壊す→戻すサイクルの後は、必ず `git status --short` で対象ファイルが元の（意図した）
  差分に戻っているか確認してから次の作業に進む。
