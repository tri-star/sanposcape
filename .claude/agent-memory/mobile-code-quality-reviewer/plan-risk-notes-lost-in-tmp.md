このプロジェクトの知識管理は3層モデル: 決定事項はADR、エージェントの作業記憶は `.claude/agent-memory/`、
一時的な作業メモはチケットごとの一時ディレクトリ（gitignore 対象で永続しない）に置く。

実装プランには、しばしば「実機で確認すべきこと」「既知のプラットフォーム制約とそのフォールバック案」が書かれる
（例: SS-33 で「凡例の破線見本が Android で `borderStyle: 'dashed'` + 不均等な `borderWidth` により描画されない
既知の RN 制約があるので、崩れたらフォールバックに切り替える」という注意書きがプランにあったが、実装コード・ADR の
どちらにもこの注意書きは転記されていなかった）。プラン文書ごと削除されれば知見ごと失われる状態だった。

**Why**: 一時作業メモは後続セッションから参照されない前提（恒久記録から一時メモを参照しない運用になっている）。
プラン内の「あとで実機確認して分岐が必要なら直す」という指示は、実装者がその場で確認して終わりにしてしまうと、
確認結果（OKだったかフォールバックに切り替えたか）も、そもそもの制約の存在も、一時メモ削除後にコードだけを
読む次の人には伝わらない。

**How to apply**: レビュー時に実装プラン文書を読んで「実機確認」「既知の制約」「フォールバック案」の記述を
見つけたら、対応する実装ファイルやADRにその制約が一言でも転記されているか確認する。転記されていなければ
🟡 Warning として指摘する（実装の正しさそのものではなく、知見の保存場所の観点）。恒久的な後始末パターン
（レジストリ等のアーキテクチャ決定）とは違い、これは「一度きりの注意書きの保存先」の問題。
