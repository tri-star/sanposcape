# 機械的な変更をサブエージェントに任せるとき

意図が明確で量の多い変更（多数のファイルへの同じ置き換え、生成物に合わせた呼び出し側の追随、定型的なテストの追加など）だけを任せる。
設計の判断が要る変更、規約の解釈が分かれる変更は任せない（メインで行う）。

## 起動

- エージェント: `general-purpose`、`model: sonnet`
- 1回の依頼で1つのまとまった変更にする。互いに触るファイルが重ならない場合だけ、複数を並列にしてよい。
  並列にするときはコミットさせない（同じ worktree で `git add` / `commit` が競合する）。メインがまとめてコミットする

## 依頼文に書くこと

```
## 目的
<なぜこの変更をするか。1〜3行>

## やること
<対象（ファイル・パターン）と、どう変えるか。例を1つ添える>

## 完了条件
- <通すべきコマンド（例: pnpm --filter mobile typecheck / docker compose exec api pytest <対象>）>
- <変更してはいけないもの（例: 生成物 src/api/generated/ は手で編集しない）>

## 守ること
- ブランチの作成・切り替え、push はしない。コミットは <する/しない>（する場合は docs/git-commit-guideline.md に従う）
- 同じテスト・同じ手順で3回失敗したら中断して報告する
- 依頼の範囲外の問題に気づいたら、直さずに報告する

## 報告の形式
- 変更したファイルの一覧
- 実行した検証コマンドと結果
- 依頼の範囲外で気づいたこと、判断に迷ったこと
```

## 受け取った後

- 差分を自分で確かめる（報告だけで完了とみなさない）。
- 判断に迷ったことの報告があれば、メインで判断して `handover-notes.md` に記録する。
